# RPL Harness

Система без приложения: набор ролей, памяти, ритуалов и артефактов, которые превращают Codex в рабочий прототип RPL Mirror.

## Цель

Проверить, помогает ли диалоговый игровой персонаж:

- точнее увидеть текущую жизнь;
- легче сформулировать желаемую версию через 1-10 лет;
- увидеть разрыв между версиями;
- превратить разрыв в понятные квесты;
- возвращаться к выбранному вектору без ощущения токсичной оптимизации.

## Принцип

Не строим продукт сначала. Используем Codex как ручной движок продукта:

1. Диалог собирает живые данные.
2. Память сохраняет слепок и изменения.
3. Skills задают процедуры.
4. Агенты выступают как роли мышления.
5. Harness связывает все в повторяемые сессии.

## Git-First Упаковка

RPL Harness проектируется так, чтобы его можно было отдать людям через Git.

Публичная часть:

- системные документы `RPL-*.md`;
- reusable skills в `skills/`;
- шаблоны пользовательского сейва в `templates/`;
- правила приватности, онбординга, ритуалов и памяти.

Приватная часть:

- реальные пользовательские профили;
- личная память;
- фотографии и generated assets;
- финансовые модели;
- история сессий;
- любые файлы `USER/`, `users/{user_id}/` и `{USER}-*.md`.

Правило: публичный репозиторий должен позволять новому человеку создать свой RPL-инстанс, но не должен раскрывать пилотный инстанс другого человека. Подробный план: [RPL-GIT-DISTRIBUTION.md](RPL-GIT-DISTRIBUTION.md).

## Правило Разделения И Переноса

Все, что сначала делается на персональном примере пилотного пользователя, нужно сразу формулировать в трех слоях:

- **System Layer**: обезличенное правило, процедура, роль агента, шаблон вопроса или формат данных, который можно переиспользовать для любого пользователя.
- **User Instance Layer**: конкретный слепок, вопрос, квест, метрика, профиль или артефакт для жизни одного пользователя.
- **Derived Pattern Layer**: обобщение, которое родилось из личного случая, но стало правилом без персональных деталей.

Личные данные остаются в пользовательском слое. В Harness переносятся только механики, формулировки, ритуалы, проверки реальности и способы превращать жизнь в честного персонажа. Подробное правило границ: [RPL-DATA-BOUNDARIES.md](RPL-DATA-BOUNDARIES.md).

## Роли Агентов

Это не отдельные технические процессы по умолчанию, а роли, которые Codex может включать по задаче.

| Роль | Задача |
|------|--------|
| Mirror Interviewer | Собирает слепок текущего персонажа через живой диалог. |
| Character Artist | Превращает слепок в визуальный промпт и изображение. |
| Future Self Cartographer | Помогает описать персонажа через выбранный горизонт времени. |
| Gap Analyst | Сравнивает текущего и будущего персонажа, выделяет разрыв. |
| Quest Designer | Превращает разрыв в квесты на 7 дней, месяц и сезон. |
| Memory Curator | Обновляет профиль, фиксирует решения, не смешивает версии. |
| Weekly Reflector | Проводит регулярное зеркало: что изменилось, что буксует, какой следующий ход. |
| Life Compass Analyst | Проверяет баланс жизни по ключевым доменам и ищет не "идеальный круг", а перекосы, которые мешают выбранному персонажу. |
| Cultural Curator | Подбирает практики, книги, фильмы, разговоры и паузы под текущий сезон персонажа. |

## Память И Границы Данных

Память живет в markdown-файлах внутри проекта, чтобы она была прозрачной и редактируемой. Системные файлы и пользовательские файлы должны быть разделены.

### System Layer

| Файл | Роль |
|------|------|
| [RPL-CONCEPT.md](RPL-CONCEPT.md) | Канон идеи. |
| [RPL-DATA-BOUNDARIES.md](RPL-DATA-BOUNDARIES.md) | Правила разделения системного Harness и пользовательских данных. |
| [RPL-ONBOARDING-RITUALS.md](RPL-ONBOARDING-RITUALS.md) | Повторяемый протокол онбординга, ритуалов, памяти и квестов. |
| [RPL-LIFE-COMPASS.md](RPL-LIFE-COMPASS.md) | Черновик универсальной диагностики баланса и направления жизни. |
| [RPL-HUMAN-JOURNEY.md](RPL-HUMAN-JOURNEY.md) | Универсальный путь пользователя: инструменты, практики, поддержка, культурные рекомендации. |

### User Instance Layer

Пользовательский слой хранится отдельно от Harness. Рекомендуемая структура:

```text
USER/
  USER-MEMORY.md
  USER-PROFILE.md
  USER-FUTURE-{horizon}.md
  USER-LIFE-COMPASS.md
  USER-GAP-{horizon}.md
  USER-QUESTS.md
  USER-WEEKLY-MIRROR.md
  USER-EVIDENCE-LOG.md
  assets/
```

## Основные Сессии

### 0. Onboarding

Когда человек впервые входит в RPL.

Выход:

- согласие и границы;
- выбранный стартовый режим;
- первый слепок;
- first character card;
- первый 7-дневный квест;
- решение, что сохранять в пользовательскую память.

Подробный протокол: [RPL-ONBOARDING-RITUALS.md](RPL-ONBOARDING-RITUALS.md).

### 1. Current Mirror

Когда нужно увидеть текущую версию.

Выход:

- класс персонажа;
- локация;
- текущий архетип;
- статы;
- дебаффы;
- символы окружения;
- визуальный промпт;
- изображение.

### 2. Future Mirror

Когда нужно описать версию через X лет.

Выход:

- future character card;
- визуализация будущего персонажа;
- отличия от текущей версии;
- новые способности, ресурсы и ограничения.

### 3. Gap To Quest

Когда нужно перейти от красивой картинки к действию.

Выход:

- 3 главных разрыва;
- 3 skill tree ветки;
- 1 квест на 7 дней;
- 1 сезонная ставка;
- критерий реального прогресса.

### 4. Weekly Mirror

Регулярный ритуал.

Вход:

- что сделал за неделю;
- что не сделал;
- что изменилось в энергии;
- какой был главный конфликт недели;
- какие сигналы из реальности появились.

Выход:

- честное зеркало;
- обновление дебаффов/статов;
- следующий квест;
- один вопрос, который нельзя обойти.

### 5. Life Compass

Когда нужно понять, куда ведется жизнь в целом, а не только один квест или один разрыв.

Выход:

- карта доменов жизни;
- оценка текущего состояния и желаемого состояния;
- 1-3 перекоса, которые требуют внимания;
- домены, которые нельзя оптимизировать сейчас без вреда;
- вопросы о ценностях, ограничениях и цене желаемого будущего;
- следующий маленький эксперимент в реальности.

### 6. Season Review

Когда нужно пересобрать курс без ощущения провала.

Выход:

- название текущего сезона;
- что выросло, устало или перестало быть целью;
- обновленный фокус;
- 1-3 сезонных квеста;
- список того, что больше не нужно тащить.

## Skills

Skills — это переиспользуемые процедуры RPL. Они должны быть достаточно конкретными, чтобы агент мог выполнить сессию, и достаточно обезличенными, чтобы их можно было дать любому пользователю.

| Skill | Когда использовать |
|------|--------------------|
| [rpl-onboarding](skills/rpl-onboarding/SKILL.md) | Новый пользователь, границы, режим старта, первый безопасный слепок |
| [rpl-current-mirror](skills/rpl-current-mirror/SKILL.md) | Текущий персонаж, факты, ресурсы, дебаффы, символы |
| [rpl-future-mirror](skills/rpl-future-mirror/SKILL.md) | Будущий персонаж через выбранный горизонт |
| [rpl-life-compass](skills/rpl-life-compass/SKILL.md) | Диагностика доменов жизни, сезонов, перекосов и next experiments |
| [rpl-quest-designer](skills/rpl-quest-designer/SKILL.md) | Превращение разрыва или домена в маленький квест с evidence |
| [rpl-weekly-mirror](skills/rpl-weekly-mirror/SKILL.md) | Недельное зеркало: события, избегание, evidence, следующий ход |
| [rpl-season-review](skills/rpl-season-review/SKILL.md) | Пересборка сезона раз в 1-3 месяца |
| [rpl-freedom-number](skills/rpl-freedom-number/SKILL.md) | Финансовая карта свободы без публикации личных чисел |

| [rpl-memory-curator](skills/rpl-memory-curator/SKILL.md) | Сохранение памяти, обезличивание паттернов, Git safety |

## Ритуальный Ритм

Минимальный ритм RPL:

- Daily Micro-Check: 2-5 минут, по желанию.
- Quest Check-In: 1-3 раза в неделю.
- Weekly Mirror: раз в неделю.
- Monthly Compass: раз в месяц.
- Season Review: раз в 1-3 месяца.

Правило: если ритуал не помогает человеку возвращаться к реальности и выбранному вектору, его нужно упростить или убрать.

Фразы, которые должны запускать режим RPL:

- "RPL Mirror: обнови меня сейчас"
- "RPL Mirror: сделай future self"
- "RPL Mirror: сравни сейчас и через 10 лет"
- "RPL Mirror: дай квест на неделю"
- "RPL Mirror: weekly review"
- "RPL Mirror: обнови память"
- "RPL Mirror: начать онбординг"

- "RPL Mirror: season review"

## Правила Тона

- Не говорить языком hustle culture.
- Не превращать жизнь в таблицу эффективности.
- Не льстить и не драматизировать.
- Отделять честное зеркало от публичного перформанса.
- Держать две оптики одновременно: игра и реальная жизнь.
- Любой квест должен быть проверяемым в реальности.
- Сначала спрашивать границы, потом углубляться.
- В плохой сезон не навязывать рост.
- Не сохранять личные данные без явной пользы для пользователя.

## MVP-Проверка

Первая жизнеспособная проверка:

1. Собрать текущий персонаж.
2. Сгенерировать картинку.
3. Собрать персонажа через 10 лет.
4. Сгенерировать вторую картинку.
5. Сравнить версии.
6. Дать первый 7-дневный квест.
7. Через неделю сделать Weekly Mirror.

Критерий успеха: хочется вернуться к системе не ради картинки, а ради следующего честного зеркала.
