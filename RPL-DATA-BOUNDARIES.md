# RPL Data Boundaries

Как разделять универсальную систему RPL Harness и личные данные конкретного пользователя.

## Главный Принцип

RPL должен быть устроен как движок и пользовательский сейв.

- **System Layer**: правила, роли, сессии, шаблоны, тон, алгоритмы, вопросы, форматы.
- **User Instance Layer**: личная память, профиль, фотографии, квесты, финансовые расчеты, отношения, история сессий.
- **Derived Pattern Layer**: обезличенные выводы из работы с пользователем, которые можно превратить в общее правило.

Нельзя смешивать эти слои. Если личный факт попал в системный документ, его нужно вынести в пользовательский профиль, а в системе оставить только обобщенный паттерн.

## Что Является Системным

Системные документы можно переиспользовать для любого человека.

В них допустимы:

- роли агентов;
- протоколы сессий;
- список доменов Life Compass;
- правила тона;
- шаблоны вопросов;
- схемы файлов;
- критерии качества квестов;
- правила приватности;
- примеры без личных данных;
- культурные рекомендации, если они не привязаны к конкретному человеку.

В них нельзя хранить:

- имена пользователя и близких;
- возраст, локацию, работу, доход, здоровье;
- фотографии и визуальные артефакты конкретного человека;
- личные страхи, планы, финансовые числа;
- историю личных сессий;
- ссылки на персональные файлы пользователя как обязательную часть протокола.

## Что Является Пользовательским

Пользовательский слой — это один конкретный "сейв" RPL.

В нем живут:

- текущий персонаж;
- future self;
- личный Life Compass;
- active quests;
- weekly mirrors;
- evidence log;
- фотографии и generated assets;
- личные финансовые модели;
- история сессий;
- открытые вопросы;
- имена людей и контекст отношений.

## Что Является Derived Pattern

Derived Pattern — это мост от частного к общему.

Пример:

- Личный факт: "Пользователю важно снизить тревогу о будущем через финансовую модель свободы".
- Derived Pattern: "Если пользователь формулирует финансовую цель как свободу, агент должен проверить, не скрывается ли под ней потребность в безопасности".

Derived Pattern можно переносить в Harness. Личный факт — нельзя.

## Минимальная Структура Повторяемого Инстанса

Для нового пользователя создается отдельный набор файлов по шаблону:

```text
users/{user_id}/
  USER-MEMORY.md
  USER-PROFILE.md
  USER-FUTURE-{horizon}.md
  USER-LIFE-COMPASS.md
  USER-GAP-{horizon}.md
  USER-QUESTS.md
  USER-WEEKLY-MIRROR.md
  USER-EVIDENCE-LOG.md
  assets/
```

В ручном прототипе пользовательские файлы могут временно лежать рядом с системными и иметь персональный префикс. При упаковке в публичный Harness их нужно перенести в приватный пользовательский инстанс или исключить из публичного пакета.

## Git Safety

Публичный Git-репозиторий должен содержать только Harness:

- `RPL-*.md`, если файл не содержит личных данных;
- `skills/`;
- `templates/`;
- документацию по установке и использованию.

Пользовательские сейвы должны жить вне публичного репозитория или в ignored-папках. Текущий рабочий прототип использует `.gitignore`, чтобы не добавить приватный слой случайно.

## Правило Именования

Системные файлы:

- `RPL-*.md`
- не содержат персональных данных;
- могут быть опубликованы или переиспользованы.

Пользовательские файлы:

- `{USER}-*.md` или `users/{user_id}/*.md`;
- содержат персональные данные;
- не публикуются без явного обезличивания.

Шаблоны:

- `TEMPLATE-*.md`;
- содержат поля и инструкции, но не реальные данные.

## Протокол Добавления Новой Идеи

Когда во время работы появляется новая идея:

1. Сначала записать личный факт в пользовательскую память.
2. Сформулировать обезличенный паттерн в 1-3 предложениях.
3. Решить, куда он относится:
   - роль агента;
   - протокол сессии;
   - шаблон вопроса;
   - правило приватности;
   - тип квеста;
   - культурная рекомендация.
4. Добавить паттерн в системный документ без имен и личных деталей.
5. Если паттерн пока не проверен, пометить его как гипотезу.

## Протокол Обезличивания

Перед публикацией или переиспользованием Harness:

1. Просканировать системные документы на имена, локации, компании, возраст, суммы, фото и ссылки на личные ассеты.
2. Вынести найденное в пользовательский слой.
3. Заменить личные примеры на абстрактные:
   - "пользователь";
   - "партнер";
   - "ребенок";
   - "работа";
   - "город";
   - "финансовая цель".
4. Проверить, что системный документ можно дать новому человеку без раскрытия чужой жизни.
5. Проверить, что по системному документу можно создать новый пользовательский инстанс.

## Главная Проверка

Если фразу можно использовать для любого человека — это Harness.

Если фраза отвечает на вопрос "что происходит в жизни этого конкретного человека?" — это User Instance.

Если фраза родилась из личного случая, но стала правилом без личных деталей — это Derived Pattern.
